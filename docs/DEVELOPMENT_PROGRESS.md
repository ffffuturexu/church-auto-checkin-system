## 2026-11 进展

### 会友登记与生日资料完善（v0.7.3）
- **生日和年龄**：支持完整生日或仅月日，登记时年龄独立记录并保存登记日期，不推算出生年份或自动更新年龄；完整生日与部分生日或登记年龄不能同时存在。
- **兼容迁移与提醒**：SQLite 启动迁移幂等新增字段并保留旧生日；关怀生日接口和生日提醒支持无年份生日，未知岁数不作推算，非闰年的 2 月 29 日按 2 月 28 日处理。
- **新增流程**：提交前核对资料，支持可选照片及预览；创建后分别提示照片和主日签到结果。使用客户端 UUID 支持创建请求幂等重试，上传结果不确定时提示先核实，避免重复操作。
- **管理界面**：新增与编辑支持生日和登记年龄；新增表单适配平板横竖屏和窄屏，生日/年龄、照片/备注成组排列并对齐控件。
- **回归测试**：补充部分生日、年龄校验和更新、闰日提醒、幂等创建与 SQLite 迁移测试；关怀简报集成测试使用生产数据库的临时副本，避免写入原库。
- **验证结果**：生日与关怀简报定向测试 20 项通过；非集成套件 84 项通过、2 项失败，仍为既有的关怀 CSV 表头预期和日期窗口测试问题。

### 摄像头链路诊断日志（v0.7.2）
- **周期状态**：应用运行期间每 10 秒记录摄像头出帧、识别状态、队列及进程资源，并通过 `ss` 采集本进程与摄像头端口的 TCP 连接指标。
- **流异常**：通过 systemd journal 提取本进程常见 OpenCV/FFmpeg 流超时、RTSP 连接及编码解码异常；保留事件原始时间，不记录 RTSP 地址或凭据。
- **存储与边界**：日志写入 Git 忽略的 `logs/camera.log`，5 MiB 轮转并保留 5 个旧文件；采集依赖目录写权限、`ss` 和 journal 访问，不替代摄像头/AP 日志或抓包，也不会自动修复断流。
- **验证**：摄像头诊断、事件分发集成及基础 API 定向回归共 46 项通过；已对本机 TCP 连接和历史 FFmpeg 日志过滤进行只读验证。当前运行服务须在维护时段重启后启用采集器，并按需重新启动视频流。

### 事件消费者可靠性与队列优化（v0.7.1）
- **异常恢复**：按事件捕获异常并记录类型和原始 ID；监督任务在消费者意外退出时退避重启，关闭时等待正在执行的数据库操作完成。
- **降低阻塞**：同步数据库操作在线程中执行，业务事件保持串行；提交后的 WebSocket 通知进入独立有界广播队列，慢连接不阻塞后续数据库写入。
- **调试帧隔离**：调试视频使用最新帧单槽与独立广播循环，旧帧可被覆盖，不再占用业务事件队列。
- **监控与恢复**：健康检查及自检接口增加队列水位、按类型丢弃和失败数、耗时、重启次数及 WebSocket 发送失败指标；队列接近满载、丢弃和异常时记录日志。无图片的孤立签到使用占位图，避免违反数据库非空约束。
- **边界**：队列仍在内存中；业务队列满时丢弃最旧事件，广播队列满时丢弃新通知，失败业务事件不会自动重试。正常关闭先停止生产并排空业务事件，广播最多等待五秒。
- **验证**：事件分发、识别逻辑和基础 API 定向回归共 56 项通过；非集成全量测试另有两项关怀测试失败，涉及 CSV 表头预期和日期窗口，与本次事件管道改动无关。

## 2026-09 进展

### 签到来源模型与历史数据迁移
- **字段语义拆分**：保留 `AttendanceRecord.method` 表示执行方式，新增 `source` 表示业务来源，区分 `recognition`、`manual_search`、`pending_queue` 和 `backfill`。

- **接口与统计**：签到历史 API、CSV 导出和 Dashboard 增加来源字段及来源分类统计，同时保留原有 `manual_checkins` 汇总口径。

### 识别事件模型重构（2026-06-19）
- 业务事件统一为 `recognition.success`、`recognition.pending`、`recognition.unknown`，并保留向后兼容的 `check_in` / `unknown_face` 出站映射，便于平滑迁移前端消费端。
- 事件载荷规范：在 `data` 中统一提供 `decision`（`success|pending|unknown`）与 `queue_kind`（`pending_review|stranger|null`）字段，前端可直接据此做展示与筛选。
- 新增 `max_finalize_sec` 超参数，并在运行时实施超参数约束：`stranger_max_similarity < pending_min_similarity <= vote_threshold <= absolute_threshold`。
- 待复核与陌生人队列采用 `idle-first` 最终化策略；为避免无限等待增加最长等待时间回退（`max_finalize_sec`）。
- 后端增加判重逻辑，避免同一识别事件重复创建 `RecognitionLog` 或 `UnknownFaceCase`；同时修复了因重复索引引发的 SQLite 建表错误（移除多余索引）。
- 前端联动：`reception.html`（接待页）与 `debug.html`（调试页）已做兼容更新；接待页将“异常抓拍队列（Unknown）”改为“待处理队列”，并区分 Pending / Unknown 展示；调试页超参数标签与 Channel A 事件色标更新。
- 测试：调整并扩展了相关单元测试与集成测试，目标测试组已通过。

### 识别引擎补充变更（2026-06-27）
- **识别引擎（Recognition Engine）**：Pending 候选快照改为双缓存 `latest` + `best`；新增 `_is_snapshot_usable` 与 `_select_pending_snapshot`；新增 `_encode_pending_snapshot_with_fallback` 编码回退；修正 finalize 时序（先读 snapshot，再 clear state）；补充 `PendingSnapshotTuple` 五元组类型注解。
- **事件与日志**：`RecognitionEngine._commit_checkin` 解耦 `method`（签到渠道）与 `recognition_reason`（识别日志原因）；`recognition.pending` / `recognition.unknown` / `recognition.success` 的 payload schema 保持不变。
- **运维与调试**：修正 finalize 的 reason 判定顺序（`ambiguous_margin` → `weak_consensus` → `vote_timeout`），并为被丢弃候选补写 `insufficient_frames` 与 `weak_candidate` 日志。
- **文档与测试**：该次调整保持对外事件 schema 向后兼容，建议在 CI 中运行 `tests/test_recognition_engine_logic.py` 验证行为。

注：以上 6 月改动均为最小侵入式修复，未修改 `recognition.pending` 的事件字段名或主流程的 stranger / success 路径。
