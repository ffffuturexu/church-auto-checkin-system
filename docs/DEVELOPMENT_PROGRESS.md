## 2026-07 进展

### 接待照片查找排序优化（v0.5.5）
- **已签到排序**：在接待页照片查找中选择“已签到”后，按所选场次的签到时间倒序显示会友，最近签到者优先。
- **查询稳定性**：为本场签到时间排序增加相关子查询，保留其他照片查找模式原有的近期活跃排序。
- **回归测试**：补充不同签到时间的排序测试，并在 `autocheckin` conda 环境中验证通过。

### 每周关怀简报生产化（v0.5.3）
- **周报脚本上线**：新增 `scripts/send_weekly_care_brief.py`，通过内部 API 拉取签到与关怀数据，使用确定性模板渲染周报正文并通过 SMTP 发送。
- **发送日志落库**：新增 ORM 模型 `WeeklyReportLog`（表 `weekly_report_logs`），记录生成/发送状态（`generated` / `sent` / `failed`）、收件人、主题与正文，便于审计追踪。
- **后台接口补齐**：新增 `GET/PUT /system/weekly-report-config`、`GET /system/generate-weekly-brief`、`POST /system/send-weekly-brief`、`GET /system/weekly-report-latest`。
- **管理页支持**：管理后台新增“每周简报”区域，可查看最近简报并触发生成/发送。
- **运维定时任务**：新增 `scripts/systemd/send_weekly_care_brief.service` 与 `.timer`，支持每周定时发送；敏感配置通过 `/etc/default/send_weekly_care_brief`（600 权限）管理。
- **测试补充**：新增 `tests/test_weekly_care_brief.py`，并通过 `autocheckin` 环境验证。

### 接待页补签与照片查找修复
- **未知卡片补签场次修正**：修复接待页“待处理队列”中点击“是”时的场次落点，未知卡片现在会优先绑定当前选中的 `event_id`，避免下午意语场误写入同日早上的中文场。
- **照片查找筛选增强**：按照片查找新增“已签到 / 未签到”筛选，返回结果支持同时包含有照片和无照片的会友，便于接待同工按签到状态快速定位目标成员。
- **回归测试补强**：为未知卡片补签路由与照片查找筛选补充定向回归测试，并在 `autocheckin` conda 环境中验证通过。

## 2026-06 进展

### 运维稳定性与调试控制
- **WebSocket 超时保护**：为 Channel A/B 广播增加强制超时，避免慢连接拖垮事件分发。
- **运行时监控补强**：状态看板新增队列负载卡片，展示帧队列与事件队列占用比。
- **调试控制增强**：调试页新增运行时重启按钮与调试视频开关，避免调试视频影响核心识别链路。
- **负载瘦身**：`check_in` 事件出站前移除 base64 图像字段，降低 Channel A 传输成本。
- **调试标注优化**：调试画面叠字改用成员名称显示，相似度保留；新增识别标注开关与红/黄/绿三段相似度颜色提示；中文姓名标注改用 PIL + CJK 字体渲染，修复 `????` 问题。
- **调试台超参数改版**：当前参数改为只读展示区，编辑输入与默认参数恢复按钮分离，方便在不打断查看状态的情况下热更新与回滚。
- **接待页启动优化**：状态告警增加“正在建立连接”待定状态，完善启动阶段的状态读取重试机制；照片选择器新增首屏自动填充逻辑，确保大屏视野下候选人自动补填。

### 生日提醒功能
- 新增 `scripts/send_birthday_reminders.py`：基于系统本地时区计算会友生日，支持 `BIRTHDAY_REMINDER_DAYS_AHEAD`（默认 0）、收件人、SMTP 配置与 dry-run 模式。
- 增加 ORM 表 `birthday_reminder_logs`（模型 `BirthdayReminderLog`）用于记录每次脚本运行结果（无生日/dry-run/已发送）。
- 提供 `scripts/systemd/birthday_reminder.service` 与 `scripts/systemd/birthday_reminder.timer` 示例，建议将凭据放在 `/etc/default/birthday_reminder` 并用 systemd timer 每天 08:00 触发。

### 识别事件模型重构（2026-06-19）
- 业务事件统一为 `recognition.success`、`recognition.pending`、`recognition.unknown`，并保留向后兼容的 `check_in` / `unknown_face` 出站映射，便于平滑迁移前端消费端。
- 事件载荷规范：在 `data` 中统一提供 `decision`（`success|pending|unknown`）与 `queue_kind`（`pending_review|stranger|null`）字段，前端可直接据此做展示与筛选。
- 新增 `max_finalize_sec` 超参数，并在运行时实施超参数约束：`stranger_max_similarity < pending_min_similarity <= vote_threshold <= absolute_threshold`。
- 待复核与陌生人队列采用 `idle-first` 最终化策略；为避免无限等待增加最长等待时间回退（`max_finalize_sec`）。
- 后端增加判重逻辑，避免同一识别事件重复创建 `RecognitionLog` 或 `UnknownFaceCase`；同时修复了因重复索引引发的 SQLite 建表错误（移除多余索引）。
- 前端联动：`reception.html`（接待页）与 `debug.html`（调试页）已做兼容更新；接待页将“异常抓拍队列（Unknown）”改为“待处理队列”，并区分 Pending / Unknown 展示；调试页超参数标签与 Channel A 事件色标更新。
- 测试：调整并扩展了相关单元测试与集成测试，目标测试组已通过。

### 识别引擎补充变更（2026-06-27）
- **识别引擎（Recognition Engine）**：Pending 候选快照改为双缓存 `latest` + `best`；新增 `_is_snapshot_usable` 与 `_select_pending_snapshot`；新增 `_encode_pending_snapshot_with_fallback` 编码回退；修正 finalize 时序（先读 snapshot，再 clear state）；补充 `PendingSnapshotTuple` 五元组类型注解。
- **事件与日志**：`RecognitionEngine._commit_checkin` 解耦 `method`（签到渠道）与 `recognition_reason`（识别日志原因）；`recognition.pending` / `recognition.unknown` / `recognition.success` 的 payload schema 保持不变。
- **运维与调试**：修正 finalize 的 reason 判定顺序（`ambiguous_margin` → `weak_consensus` → `vote_timeout`），并为被丢弃候选补写 `insufficient_frames` 与 `weak_candidate` 日志。
- **文档与测试**：该次调整保持对外事件 schema 向后兼容，建议在 CI 中运行 `tests/test_recognition_engine_logic.py` 验证行为。

注：以上 6 月改动均为最小侵入式修复，未修改 `recognition.pending` 的事件字段名或主流程的 stranger / success 路径。

## 2026-05 进展

### 管理后台移动端与分组体验优化
- **会友分组选择与编辑**：新增会友的分组输入改为可下拉选择，自动复用系统中的分组集合；修复分组下拉交互，支持选择与手动输入。
- **列表与报表展示优化**：会友列表照片列去除了多余文字，直接展示缩略图或“无图”占位；手机端的历史签到列表已改为卡片式的纵向展示，以适配小屏设备。

### 照片缩略图与报表布局优化
- **照片缩略图机制**：增加照片的缩略图生成与下载链路（上传、替换、删除时同步维护），接待页和管理后台直读缩略图，大幅减少大图传输开销。
- **报表展示调整**：签到记录中默认居中展示缩略图，调整了报表的列宽与间距，改善密集表格模式下的可见性。

### 关怀中心设计与开发
- **风险展示与逻辑校验**：风险等级采用更直观的中文分类（低/中/高）；界面补充了指标的计算公式。复核连续缺席指标统计逻辑，完善并巩固定了多维度的风险评估体系。
- **成员检索增强**：关怀中心支持按姓名、拼音全拼及首字母模糊匹配，降低了过滤逻辑到后端的耦合。
- **数据呈现与后台交互**：档案数据剥离了冗余的差值趋势信息。导出报表的表头实现全中文化，管理后台已支持刷新后保持上一活动的 Tab 页面。

### 接待页打磨与响应式优化
- **状态告警与排版**：系统状态移至顶部并改用告警条样式，对摄像头异常、识别离线等状况分别明确提示；重构工具栏及 `.hero-service` 的 flex 布局，减少无效空间。
- **动态模式切换**：支持在“签到模式”与“完整模式”间平滑切换，前者降噪后者可审计系统事件；动态信息流补充了成员中文姓名的展示。
- **照片选择器与新人筛选**：增加“只看新人”视图过滤（含无照片人员），照片选择器支持基于场次的连续分页拉取；修复了性别过滤失效的联动问题。
- **交互与连续签到**：搜索面板卡片签到后不再自动清空状态进而支持针对同一批结果连续签到；多设备（手机单列/平板多列）的断点控制进行微调。照片侧栏切换交互改为 Toggle 模式并避免在自动刷新时被误触发。

### 接待检索体验增强
- **检索聚合与语音支持**：接待页左侧加入独立的查人区域（展示卡片网格），兼容基于姓名、中文名、拼音缩略词等手段进行检索，同时补充了语音输入的交互提醒。
- **干扰要素移除**：移除补签流程中多余的交互状态以提升专注度。

### 接待体验与噪声抑制优化
- **参数调优**：下调识别阈值至 0.70 提升低画质召回率；提升匹配去重差值 Margin 门槛至 0.20 降低相似人群的误判率，修改并实时生效了热更新参数。
- **去重策略优化**：动态看板采取“每人每天唯一”的高效降压规则；补签未匹配图片的体积与长宽进行有效压制；补签支持按高匹配度自动推送至快捷一键操作。

## 2026-04 进展

### 统计口径、筛选与时区修正
- **统一时区处理**：所有签到、推送、前端展示逻辑均同步应用基于 `Europe/Rome` 时区标准。
- **统计报表修复**：修复筛选组件在不同后端架构处理兼容性上导致的失效；补充后端报表中对星期日的数据聚合限定防止周中混入，校对了本年主日签到的均值权重测算标准。

- **历史资料入库**：处理整合并成功入库 11790 行左右两份老格式考勤 CSV 表；引入“同一主日依不同语种拆分为子场次”、“专属映射”等幂等过渡策略确保数据落组妥当。
- **人脸库桥接简化**：确立主键直连 `members.id`，撤销不必要中间表 `face_profiles`；伴生相应的 SQLite 数据结构无缝迁移以剔除后端检索成本。

### 会友字段与状态流转补强
- **逻辑字段整理**：收敛“年龄”仅作为按 `birthday` 推演展示使用并从久置化中废弃；补充人员 `note` 及是否携带人脸照等检索手段。
- **信息保护**：开发新增的“物理删除与状态位恢复”两条双反向管道支持成员的安全管理维护。

### 稳定性与防梗阻设计
- **推流抗阻塞设计**：重构 `recognition_engine` 转并改由多线程承接推流校验请求；去除全局锁定采用特征坐标缓存处理抓拍业务。

- **事件集成与看板支持**：发布业务自检及常规信息统计看板展示；建设双通道（签发消息、带定帧视频推送流）及 Websocket 后台事件驱动中心，完成相应高强度整合级单元测试。

### 人脸与相册模块功能投落
- 完成由 CompreFace 进行成员和其携带人脸 CRUD 全周期闭环接入；对接“暂缓补签”对照片关联的操作映射。支持后台界面上单图上传/替换更新至云同步的实时渲染流程。
